# 在帆软 FineBI 中复刻这份看板

本文件按 FineBI 6.x 的操作路径，给出数据集、计算字段、组件与仪表板配置，使成品与 `dashboard/index.html` 的信息结构一致。FineBI 5.x 的菜单名称略有差异，逻辑相同。

## 1. 数据准备

1. **上传数据**：`数据准备 → 添加数据 → 本地文件`，分别上传 `data/fact_sales.csv`、`data/fact_fulfillment.csv`、`data/dim_date.csv`。
2. **字段类型**：
   - `date` 改为"日期"（yyyy-MM-dd）；
   - `gmv`、`refund_amount` 为数值（两位小数）；`orders`、`visitors`、`refund_orders` 为整数；
   - `platform`、`category`、`channel`、`sla_bucket` 为文本。
3. **建立数据模型**：新建"数据模型"，添加三张表，按以下关系关联（均为事实表 ← 维表）：

| 维表字段 | 事实表字段 |
| --- | --- |
| dim_date.date | fact_sales.date、fact_fulfillment.date |
| fact_sales.platform / fact_fulfillment.platform | 由平台字段生成的公共维度 |
| fact_sales.category / fact_fulfillment.category | 由品类字段生成的公共维度 |
| fact_sales.channel | 渠道（仅 fact_sales） |

FineBI 6 可在数据模型中把 `platform`、`category` 标记为"公共维度"，避免两张事实表各建一套维表导致筛选不联动。

4. **月份字段**：在 `dim_date` 上新增计算字段

```
月份 = LEFT(date, 7)
```

用于横轴分组与同环比。

## 2. 计算字段

FineBI 的计算字段是**聚合后表达式**，与 Power BI 的度量值写法不同，但口径一致。在"数据模型 → 计算字段"或组件内"添加计算字段"均可。

| 字段名 | 公式 | 说明 |
| --- | --- | --- |
| GMV | `SUM(gmv)` | 支付口径，不扣退款 |
| 订单量 | `SUM(orders)` | 支付订单数 |
| 访客数 | `SUM(visitors)` | 各渠道 UV 相加，未去重 |
| 客单价 | `SUM(gmv) / SUM(orders)` | 结果为金额，保留 0 位小数 |
| 支付转化率 | `SUM(orders) / SUM(visitors)` | 百分比，保留 2 位 |
| 退款率 | `SUM(refund_orders) / SUM(orders)` | 百分比，保留 1 位 |
| 退款金额 | `SUM(refund_amount)` | 金额 |
| 48h 订单 | `SUM(IF(OR(sla_bucket = "0-12h", sla_bucket = "12-24h", sla_bucket = "24-48h"), orders, 0))` | 来自 fact_fulfillment |
| 48h 履约达成率 | `SUM(IF(OR(sla_bucket = "0-12h", sla_bucket = "12-24h", sla_bucket = "24-48h"), orders, 0)) / SUM(orders)` | 百分比，保留 1 位 |
| 履约加权时长 | `SUM(orders * 时效中值) / SUM(orders)` | 需新增"时效中值"字段，见下 |
| 平台 GMV 占比 | 快速计算 → 占比（对 SUM(gmv)） | 或 `SUM(gmv) / TOTAL(SUM(gmv))`（视版本） |

"时效中值"在 `fact_fulfillment` 上新增：

```
时效中值 = IF(sla_bucket = "0-12h", 6, IF(sla_bucket = "12-24h", 18, IF(sla_bucket = "24-48h", 36, IF(sla_bucket = "48-72h", 60, 96))))
```

同环比不建议手写公式：把横轴设为 `dim_date.月份`，对 GMV 使用**快速计算 → 环比 / 同比**，FineBI 会按日期粒度自动错位取数，避免分母口径错误。

## 3. 组件配置

| 面板 | FineBI 组件 | 字段拖拽 | 关键设置 |
| --- | --- | --- | --- |
| KPI 行 | 指标卡（6 个） | 指标：GMV、订单量、客单价、支付转化率、退款率、48h 履约达成率 | 每个指标卡加"环比/同比"指标；数值格式与看板一致；卡片底色白、左侧 3px 主题色边条 |
| GMV 日趋势 | 折线图 | 横轴：`date`；纵轴：GMV；颜色：平台 | 过滤组件选"平台"；开启"标记大促区间"（用矩形标注或把 `促销名称` 作为颜色分组） |
| 平台结构 | 分组表 | 行：平台；指标：GMV、GMV 占比、客单价、退款率、48h 达成率 | GMV 占比列加"数据条"，退款率列加"条件格式"（≥20% 红、≥10% 橙） |
| 品类贡献 | 条形图 | 纵轴：品类；横轴：GMV | 按 GMV 降序；开启数值标签；指标卡左下显示占比 100% 堆叠辅助 |
| 渠道结构 | 组合图（柱 + 线） | 横轴：渠道；柱：GMV；线：渠道退款率；线用右轴 | 线标签显示百分比；柱色 `#2F6BFF`，线色 `#D64545` |
| 履约时效 | 堆积柱状图（百分比） | 纵轴：平台；横轴：订单量；颜色：sla_bucket | 设为"百分比堆积"；颜色从 `#0B8F6A` 到 `#C74B4B` 五档；平台轴标签加 48h 达成率 |
| 退款异常 | 明细表 / 分组表 | 行：月份、平台、品类；指标：退款率、退款率环比 | 条件格式：环比 ≥ 2.5pp 标红；按环比降序取前 6 行 |
| 关键发现 | 文本组件 | — | 直接粘贴 README 的 5 条结论，数字已由脚本生成 |

**关于异常识别**：FineBI 6 没有窗口函数，无法像 Python 那样直接算"前 3 个月中位数基线"。复刻方式有两种：
- 推荐：用"退款率环比"作为代理指标（大促后与异常月同样会抬升），配合条件格式高亮；精确的基线算法保留在 `scripts/metrics.py`，看板异常面板的数值以 `data/metrics.json` 为准。
- 进阶：把 `data/metrics.json` 中的 `anomalies` 另存为 CSV 作为辅助明细表，直接用作预警列表的数据源。

## 4. 仪表板布局与主题

1. 新建仪表板，画布 1440 × 1600（自适应"等比缩放"）。
2. 顶部放深色标题条：背景 `#0B1424`，标题 27px 白色，右侧"合成数据"标签；KPI 卡片上浮覆盖标题条下沿 24px（用"绝对布局"手动摆放）。
3. 栅格：12 列、间距 16px，按第 3 节的顺序摆放：
   - 第一行：6 个指标卡（每张 2 列）；
   - 第二行：趋势（7 列）+ 平台结构（5 列）；
   - 第三行：品类（4 列）+ 渠道（4 列）+ 履约（4 列）；
   - 第四行：异常预警（7 列）+ 关键发现（5 列）。
4. 主题色：背景 `#F4F6FA`、卡片白、边框 `#E6EAF2`、正文 `#0F172A`、次要文字 `#79879A`；平台色 `#2F6BFF / #0AA88F / #232936 / #DF6B3A`；预警色 `#D64545`。
5. 顶部放"平台"过滤组件（下拉或按钮组），与所有组件联动；异常明细表可关闭"被联动"，避免筛选后列表为空造成误判。

## 6. 发布

- 保存仪表板后发布到"目录"，设置查看权限；可导出 PDF/Excel 作为附件。
- 定时刷新在数据为本地文件时不需要；若改为数据库直连，再配置抽取与更新频率。
